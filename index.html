Minimal reproducible OpenAI-compatible request

Keep the API Base URL as configuration, not as a browseable marketing link. The example below uses the documented AIFast endpoint; replace the environment variables with the gateway you are evaluating and never paste a live key into an issue, screenshot or public repository.

export OPENAI_BASE_URL="https://www.aifast.hk/v1"
export OPENAI_API_KEY="replace-with-a-limited-test-key"

curl -sS "$OPENAI_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"YOUR_CURRENT_MODEL_ID","messages":[{"role":"user","content":"Return only: ok"}]}'

For a useful record, retain the endpoint path, configured model ID, timestamp, HTTP status, request ID when returned, response shape, and any failure body. Then repeat with the capability that your actual workload needs rather than treating a basic 200 as complete validation.

Four verification gates

  1. Access: DNS/TLS, authentication, endpoint path, model listing where available, and the current account-callable model ID.
  2. Protocol: response structure, request ID, declared model and token arithmetic.
  3. Behavior: randomized probes, streaming, tool calls and a real workload when those capabilities are required.
  4. Production: sample size, success rate, p50/p95 latency, error distribution, cost and rollback behavior.

Common API failures

401 or 403

Check the authorization header, the account scope, accidental whitespace in a key, and whether a proxy removed the header.

404 or /v1/v1

Check whether the client appends /v1, /chat/completions or another path itself. Test the final request URL, not only the configured string.

429, timeout or 5xx

Record the response headers and retry policy. Separate rate limiting, upstream timeouts and client-side cancellation before adding fallback.

Frequently asked questions

What does an OpenAI-compatible API check verify?

It can verify request and response format, authentication, declared model ID, streaming, tool calls and observable error behavior. It cannot prove the underlying vendor model identity from one request.

Should every gateway support streaming and tool calls?

No. Test the capabilities your workload needs. A batch workflow may not need streaming or tools; an agent workflow usually needs both.

What should be recorded before production?

Record the exact endpoint path, model ID, HTTP status, request ID where available, response shape, sample size, error distribution, latency percentiles and cost.
